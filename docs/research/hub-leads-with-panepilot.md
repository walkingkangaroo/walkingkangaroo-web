Date: 2026-10-14

Round: [docs/rounds/hub-leads-with-panepilot.md](../rounds/hub-leads-with-panepilot.md)

## The question

Grant wants the home page reworked so PanePilot, the first Walking Kangaroo product to go live
(November 2026), is the lead. The four games become a short "Also in the works" list. Before that,
this repo becomes `walkingkangaroo-web`: one web repo for the hub and every future product site,
with the hub in `sites/hub/`, a shared package for the footer signature, and a root design log.
A good outcome keeps `pnpm build`, `check` and `dev` green through the move, keeps the history, and
ends with a home page that sends window cleaners to panepilot.au and keeps game followers subscribed.

The design is settled in [sites/hub/design-plan.md](../../sites/hub/design-plan.md), which Grant reviewed against the
clickable mockup (https://claude.ai/artifact/RWJKnAbkrJUm6hT6jHpkjG) on 2026-10-14.

## Options

### The repo move

#### Option A: one pure-move commit, then the workspace wiring (chosen with Grant)

- **What it is:** `git mv` the app (`src/`, `public/`, `astro.config.mjs`, `tsconfig.json`, the
  app's `package.json`) into `sites/hub/` in a commit with no edits, so Git and GitHub follow each
  file's history. A second commit adds a root `package.json` whose `build`, `check` and `dev`
  scripts run the hub's (`pnpm --filter hub …`), lists `sites/*` and `packages/*` in
  `pnpm-workspace.yaml`, keeps one root `pnpm-lock.yaml`, and points `.claude/launch.json` at the
  hub.
- **Cost:** one issue. Every path in `CLAUDE.md`, `docs/process/project.md`, the README and
  `docs/brief.md` changes. Hub-only rules move to `.claude/rules/hub.md`.
- **Risk:** a move and edits in one commit can lose rename detection. Keeping the move commit pure
  avoids that. The pull request can't be squash-merged without losing that, so Grant should use a
  merge commit, as on every pull request so far.

#### Option B: a fresh `walkingkangaroo-web` repo, with this one archived

- **What it is:** start a new repo and copy the app in.
- **Cost:** loses the history and the pull-request links unless it's imported with a subtree. The
  Linear integration needs connecting again.
- **Risk:** it's against what Grant asked for ("keeping history").

### The signature (round question 1)

- **A: the brand pack's files unchanged.** The product site chooses a variant by background. It
  follows the brand rule, and the cost is that the signature doesn't take the site's colour.
- **B: `currentColor` inline SVG, as the skill says.** It matches any site, but it recolours the
  logo, so it needs a written exception.

### Screenshots and the redesign (round question 2)

- **A: build now, add the screenshots later.** The cover-only pane and the text-only stops are a
  complete page. The screenshots issue adds the images. This is two passes over the hero, but small
  ones.
- **B: wait.** One pass, but it's blocked on the PanePilot seed, which has no date.

## What can't be known without building

- **Whether Astro 7 consumes a `.astro` component from a workspace package without config.** Old
  Astro issues (withastro/astro#3820) needed `vite.ssr.noExternal`. The cheapest test is in the
  `packages/shared` issue: import the signature into a throwaway page and run `pnpm build`.
- **How the sweep feels:** the animated mask uses `@property` and a radial-gradient mask, and is
  CSS only. The mockup shows it works in Chromium. It needs checking in Firefox and Safari, and
  only Grant can judge the timing.
- **Whether Linear's GitHub integration survives the rename.** Linear's docs are silent. Check
  Linear's Settings > Integrations > GitHub after the rename, and check that the move pull request
  links to its issue.
- **Whether `withastro/action` handles a subfolder app in a pnpm workspace.** It looks for the
  lockfile only in `path`. This matters for KAN-733 (launch), not for this milestone. Note it in
  that issue.
